The catalog carries Lattice's facts, so a client such as the admin reads them instead of guessing. Core is not released yet, so these breaking changes reach no app. What changed since the first-release notes:

- **Methods describe themselves.** A method's use case declares `summary` and `effect` statics, and they become its procedure's `docs` and `mcp` meta. A method without them, and an override with either, is a compile error and a throw at `.collection()`. A blank summary throws. An app that described a method in its MCP toolset with `.describe()` and `.effect()` drops that code.
- **Every procedure carries a `lattice` meta key:** its collection, the collection's label, and its operation, plus the relation for `list` and `set`, or the method's name. `LatticeMeta` is its type.
- **Collections have a label.** `collection(slug, { label: { singular, plural } })` is optional. Without it, the label comes from the slug. The collection exposes the resolved `label`.
- **Summaries use the label:** "Get one deal by id." instead of "Get one deals document by id.", and "Create one deal." instead of "Create a deals document.". A relation's summary names the relation in words: "List the categories of one post, by its id."
- **A ref's JSON Schema has `x-lattice-ref: '<slug>'`,** and a maskable field's has `x-lattice-maskable: true`. A maskable field now keeps the meta the app gave it, such as a `title`.
- **A sort item is an enum** of the keys the collection can sort by, ascending and descending. The error messages are unchanged. A client generated by `@ts-pf/codegen` types `sort` as a union of those keys instead of `string[]`.
